# 网络配置指南

如何配置 BaiduPCS-Rust 的网络访问选项，以控制哪些设备可以访问 Web 管理页面。

---

## 核心配置项

所有网络相关的配置在 `config/app.toml` 的 `[server]` 段：

```toml
[server]
host = "0.0.0.0"       # 监听地址
port = 18888            # 监听端口
cors_origins = []       # 跨域来源（同端口部署不需要）
```

---

## 1. `host` — 监听地址

控制后端绑定到哪个网络接口，决定了哪些设备能访问。

### 可选值

| 值 | 含义 | 谁能访问 |
|----|------|---------|
| `127.0.0.1` | 仅本机回环接口 | 只有本机浏览器可以访问 |
| `192.168.1.100` | 特定内网 IP | 同网段设备可访问（需填写实际 IP） |
| `0.0.0.0` | 所有网络接口 | 所有能连到这台机器的设备均可访问 |

### 常见场景

**场景 1：仅本机使用**

```toml
host = "127.0.0.1"
```
- 最安全，只有这台机器的浏览器能打开 Web 页面
- 手机、其他电脑均无法访问

**场景 2：指定内网段访问**

```toml
# 先查一下本机内网 IP
# Linux: ip addr | grep inet
# Windows: ipconfig
# 假设查到是 192.168.1.100，则：
host = "192.168.1.100"
```
- 只有 `192.168.1.x` 网段的设备能访问
- 优点：其他网段的设备即使能路由到也无法访问

**场景 3：多网段访问**（你的场景）

```toml
host = "0.0.0.0"
```
- 监听所有网卡
- 如果有多个内网网段（如 `172.16.0.x` 和 `192.168.0.x`）都需要访问，只能用 `0.0.0.0`
- 建议**配合 Web 密码认证使用**，防止内网其他无关设备访问

---

## 2. `port` — 监听端口

```toml
port = 18888
```

- 默认 `18888`
- 如果端口被占用，可以改为其他值（如 `8080`、`9000` 等）
- 需确保防火墙允许该端口的入站流量

---

## 3. `cors_origins` — 跨域来源

### 什么时候需要配置

```
浏览器地址栏          →  前端页面从哪加载    →  API 请求发到哪      →  是否跨域
http://A:18888        →  A:18888            →  A:18888/api/v1/...  →  ❌ 同源
http://A:5173         →  A:5173 (Vite)      →  A:18888/api/v1/...  →  ⚠️ 跨域
http://A:18888        →  A:18888            →  B:18888/api/v1/...  →  ⚠️ 跨域
```

### 简单判断方法

**不需要 CORS（`cors_origins = []`）** 的情况：
- 生产模式：后端同端口 serve 前端页面（本项目默认就是这样）
- 开发模式：使用 Vite 代理（已在 `vite.config.ts` 中配置）

**需要 CORS** 的情况：
- 前端和后端部署在不同域名/端口上
- 使用独立的 Nginx 分别 serve 前端静态文件

### 配置示例

```toml
# 同端口部署（最常见）—— 不需要 CORS
cors_origins = []

# 前端和后端分开部署
cors_origins = ["http://192.168.1.100:8080", "http://192.168.1.101:8080"]
```

## 4. 你的完整配置参考

你的网络环境：**从 `172.16.0.0/24` 和 `192.168.0.0/24` 两个网段访问**

```toml
[server]
host = "0.0.0.0"           # 两个网段都走不同网卡 / 路由，必须监听所有接口
port = 18888                # 默认端口，按需修改
cors_origins = []           # 同端口 serve 前端，不需要 CORS
```

查看本机在对应网段的 IP：

```bash
# Linux
ip addr | grep -E "172\.16\.|192\.168\."

# 输出示例
# inet 172.16.1.5/24 ...
# inet 192.168.1.100/24 ...
```

然后在其他设备的浏览器打开 `http://172.16.1.5:18888` 或 `http://192.168.1.100:18888` 即可访问。

---

## 5. 安全建议

| 配置 | 安全等级 | 说明 |
|------|---------|------|
| `host = "127.0.0.1"` | 🔒 高 | 仅本机，不需要额外认证 |
| `host = "0.0.0.0"` + Web 密码 | 🔒 高 | 任意设备可访问，但有密码保护 |
| `host = "0.0.0.0"` + 无密码 | ⚠️ 中低 | 内网任何人都能直接操作网盘 |

如果你使用 `host = "0.0.0.0"`，建议至少开启 Web 密码认证：

```toml
[web_auth]
mode = "PasswordOnly"           # 或 "PasswordAndTotp"（双因素）
```

## 6. 常见问题

**Q: 改了配置要重启吗？**
A: 是的，所有 `[server]` 段配置都需要重启生效。

**Q: 手机连不上怎么办？**
A: 检查三点：
1. 手机和服务器是否在同一个内网段
2. `host` 是否为 `0.0.0.0`（`127.0.0.1` 不行）
3. 防火墙是否放行了端口：`sudo ufw allow 18888`

**Q: 改了 `cors_origins` 后前端报跨域错误怎么办？**
A: 本项目同端口部署不需要配 CORS，设为空列表 `[]` 即可。如果报错，检查前端地址和后端地址是否同一个端口。
